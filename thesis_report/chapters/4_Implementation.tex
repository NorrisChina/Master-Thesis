\section{Experimental Parameters}
This chapter details the practical setup used to validate the theoretical models from Chapter \ref{ch:design_methodology}. For the bandwidth and $p_{desync}$ sensitivity plots in Chapter~\ref{ch:results}, all experiments are configured with a desynchronization probability of $p_{desync} = 0.1$. We evaluate two data payloads: a small 96-bit message and a larger 4001-bit message. For each payload, we test verifier lengths of $n_{ver} \in \{4, 16\}$ bits, representing a small and a large verifier size.

\section{Latency Plot Generation}
To visualize the implications of the hybrid latency model, we generate latency curves parameterized by bandwidth using the Python scripts in the \texttt{experiments/} folder.

\subsection{Parameters}
All latency plots in Chapter~\ref{sec:results_and_evaluation} use the experimental parameter grid $n_{data}\in\{96,4001\}$ bits and $n_{ver}\in\{4,16\}$ bits with $p_{desync}=0.1$. The compute overheads $t_{ver}$ are taken from empirical measurements (Table~\ref{tab:tver_results_bits}), and the collision probabilities $p_{miss}$ are computed from the theoretical bounds (Table~\ref{tab:pmiss_results_bits}).

\subsection{Logic}
For each configuration $(n_{data}, n_{ver})$ and each system (SHA-256 vs. RS-ID), the script evaluates the expected latency
\begin{equation}
    L_{ID}(B)=t_{ver}+\frac{n_{ver}}{B}+p_{desync}\,(1-p_{miss})\,\frac{n_{data}}{B}
\end{equation}
over a log-spaced bandwidth grid $B\in[B_{min},B_{max}]$. The traditional baseline is computed as $L_{trad}(B)=n_{data}/B$. The resulting curves are plotted on log-log axes to reveal the break-even regime where ID-based synchronization becomes beneficial.

The generated figures are shown in Chapter~\ref{sec:results_and_evaluation} for $n_{data}=96$ bits (Figure~\ref{fig:latency_vs_bandwidth_96bits}) and for $n_{data}=4001$ bits (Figure~\ref{fig:latency_vs_bandwidth_4001bits}).

In addition, we visualize the sensitivity to desynchronization by sweeping $p_{desync}\in[0,1]$ at a fixed bandwidth and plotting $L_{ID}$ against $p_{desync}$ for the same parameter grid (Figures~\ref{fig:latency_vs_desync_96bits} and~\ref{fig:latency_vs_desync_4001bits}).

\subsection{SHA-256}
The collision probability for a truncated hash function under the Random Oracle Model is independent of the data size and is given by Equation \ref{eq:sha_bound}:
\begin{equation}
    P_{miss}^{SHA} = 2^{-n_{ver}}
\end{equation}
The corresponding numerical values for our selected verifier lengths are reported in Table~\ref{tab:pmiss_results_bits} in Chapter~\ref{sec:results_and_evaluation}.

\subsection{RS-ID}
The collision probability for the algebraic construction is bounded by the Schwartz-Zippel Lemma, as shown in Equation \ref{eq:rsid_bound}. This bound depends on both data size ($n_{data}$) and verifier length ($n_{ver}$).
\begin{equation}
    P_{miss}^{RS} \leq \frac{\lceil n_{data,bits} / n_{ver} \rceil}{2^{n_{ver}}}
\end{equation}
The computed values for $n_{data}\in\{96,4001\}$ bits and $n_{ver}\in\{4,16\}$ bits (with the bound capped at 1 when applicable) are reported in Table~\ref{tab:pmiss_results_bits} in Chapter~\ref{sec:results_and_evaluation}. These values highlight how the theoretical safety of RS-ID degrades with larger data sizes for a fixed verifier length, a key distinction from the cryptographic approach.

\section{K-ID Parameter Sweep Setup}
\label{sec:kid_setup}
In addition to the bit-based latency evaluation, we implement the tolerance-based K-ID model introduced in Section~\ref{sec:kid_model} and perform a parameter sweep over $(K,n_{ver})$ to quantify the safety--latency trade-off of the K-ID decision rule.

\subsection{Model and Metrics}
The K-ID sweep uses a truncated SHA-256 verifier and reports four quantities: the conditional miss rate $\Pr[\mathrm{accept}\mid\mathrm{unsafe}]$ (Equation~\eqref{eq:kid_sha_bound}), the fallback rate $\Pr[\mathrm{fallback}]$ across ticks, the expected latency from the hybrid model (Equation~\eqref{eq:kid_latency}), and the speedup defined as the ratio between the traditional transmission time $(n_{data}/B)$ and the expected K-ID latency.

\subsection{State Space and Quantization}
To avoid an artificially small discrete domain (which can force the empirical miss rate to become exactly zero for moderate $n_{ver}$), the robot state is modeled as a continuous random variable and then quantized:
We sample $S_t\sim\mathcal{N}(\mu,\sigma^2)$, clip it to a physical range $[S_{min},S_{max}]$, quantize it to a resolution $\Delta$ (default $\Delta=0.1$), and hash the resulting integer index.
This yields a discrete domain size of approximately $(S_{max}-S_{min})/\Delta + 1$.

\subsection{Parameter Grid}
Unless otherwise stated, we use a 96-bit payload ($n_{data}=96$ bits) at $B=1$ Mbps with a compute overhead of $t_{ver}=2.13\,\mu s$ (SHA-256, 96 bits; Table~\ref{tab:tver_results_bits}). The robot state follows a clipped Gaussian distribution with $\mu=50$ and $\sigma=12$ on $[0,100]$ and is quantized with $\Delta=0.1$. We sweep $n_{ver}\in\{4,8,12,16\}$ and $K\in\{2,5,10,20\}$, using 200{,}000 Monte Carlo ticks per configuration with a fixed seed of 42.

\subsection{Reproducibility}
The sweep and plot generation are implemented in the \texttt{experiments/} folder:
The simulation is implemented in \texttt{experiments/kid\_parameter\_sweep.py} (optionally writing a CSV), and the plotting script \texttt{experiments/plot\_kid\_parameter\_sweep.py} reads that CSV and produces the figures used in Chapter~\ref{ch:results}.
The following commands reproduce the CSV and plots (paths are relative to the repository root):
\begin{verbatim}
python3 experiments/kid_parameter_sweep.py \
    --n-data-bits 96 --bandwidth 1e6 --ticks 200000 --seed 42 \
    --robot-mean 50 --robot-std 12 --physical-min 0 --physical-max 100 \
    --value-resolution 0.1 --t-compute-us 2.13 \
    --nver 4 8 12 16 --k 2 5 10 20 \
    --out-csv experiments/results/kid_sweep.csv

python3 experiments/plot_kid_parameter_sweep.py \
    --csv experiments/results/kid_sweep.csv --out-dir experiments/results
\end{verbatim}
